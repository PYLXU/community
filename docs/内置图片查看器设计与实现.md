# 内置图片查看器：设计与实现

> 功能定位：**基于独立画布（`IndependentCanvas`）扩展出来的图片查看器**。
> 把常见图片格式绑定到 ICC 后，双击图片即以一块「以图片为背景的独立画布」打开，
> 可以直接在图片上批注；窗口可移动/调整大小/边缘吸附分屏，每张图片一个独立窗口，
> 任务栏为每个窗口显示实时预览并可分别唤起。

## 2. 文件扩展名注册（优先实现项）

### 2.1 注册表布局

全部写在 **HKCU**（当前用户），不需要管理员权限，也不会碰到别的程序的关联：

```
HKCU\Software\Classes\InkCanvasImageViewer                      ← 共用 ProgId
    (默认)                = "PNG 图片"（文件类型描述）
    FriendlyTypeName      = "PNG 图片"
    DefaultIcon\(默认)     = "<程序目录>\InkCanvasForClass.exe",0
    shell\open\command    = "<程序目录>\InkCanvasForClass.exe" -image "%1"

HKCU\Software\Classes\.png\OpenWithProgids
    InkCanvasImageViewer  = REG_NONE（空数据）        ← 使其出现在右键「打开方式」

HKCU\Software\Classes\Applications\InkCanvasForClass.exe
    FriendlyAppName / ApplicationName = "Ink Canvas"
    ApplicationIcon  = "<程序目录>\InkCanvasForClass.exe",0
    AppUserModelID   = "InkCanvasForClass.CE"          ← 与主程序一致，任务栏图标归组
    shell\open\command = "<程序目录>\InkCanvasForClass.exe" -image "%1"
    SupportedTypes\.png = ""                            ← 声明本程序支持的类型
```

几个刻意的取舍：

* **单一 ProgId 服务全部图片格式**（`InkCanvasImageViewer` 而不是每个扩展名一个 ProgId）。
  多扩展名共用 ProgId 完全合法，且只需要维护一份 `shell\open\command`。
* **只写 `OpenWithProgids`，不抢默认值**。Windows 10/11 的默认处理程序由
  `FileExts\.ext\UserChoice`（带哈希保护）决定，程序无法合法静默改写。
  `TrySetUserDefaultProgId` 只在**不存在** `UserChoice` 时写 `HKCU\Software\Classes\.ext`
  的默认值并返回结果；需要用户确认时由 `OpenDefaultAppsSettings()` 拉起系统「默认应用」设置页。
  这条路径在设置页里由「打开系统默认应用设置」按钮显式触发，不做任何偷偷摸摸的事。
* **注销不留残留**：`UnregisterImageViewerAssociation` 只从 `OpenWithProgids` 摘掉本程序的项，
  并在没有任何扩展名再引用该 ProgId 时才删除类型定义（`AnyOpenWithProgidsReference`）。
  设置页的「清除本程序写入的关联」还会顺带清理清单里所有格式，把历史上绑定过、
  后来取消的格式一并扫干净。
* **插件关联标记互斥**：注册时会清掉扩展名键下的 `InkCanvasPluginId`，避免同一个扩展名
  同时被插件和内置查看器认领。

### 2.2 命令行启动

注册表把打开命令写成 `"...InkCanvasForClass.exe" -image "%1"`。
宿主侧的识别是 **与开关位置无关** 的：`FileAssociationManager.GetImageViewerFileFromArgs`
遍历所有参数，跳过 `-` / `/` 开头的开关，只要某个参数是**现存文件**且其扩展名
在设置里已绑定、且本机可解码，就判定为图片。

这样无论是注册表写入的 `-image "x.png"`、直接 `"x.png"`、还是把文件拖到 exe 上都能识别，
也避免了「开关和路径中间夹了别名」之类的解析问题。

判定链路：

```
IsBoundAndDecodable(ext, settings)
  = settings.IsEnabled                       // 总开关
 && ImageViewerFormats.IsDecodable(ext)       // 本机 WIC 有解码器
 && settings.BoundExtensions 含该扩展名        // 用户显式绑定
```

### 2.3 已有实例的 IPC

ICC 是单实例程序。第二个进程启动时：

1. `App.OnStartup` 检测到已有实例 → 若参数里有图片，调用
   `TrySendImageViewerFileToExistingInstance`（写 `%TEMP%\InkCanvasImageViewerFile_<guid>.tmp`
   + 置名事件 `InkCanvasFileAssociationIpc`）后自行退出；
2. 已有实例的 IPC 监听线程在 `ProcessIpcFiles` 里读到这类文件，
   在 UI 线程调用 `ImageViewerManager.OpenImage(path)`。

新前缀同时加入了 `CleanupStaleIpcFiles` 的清理列表，避免重启后重复执行上次未处理的命令。

### 3.2 设置页（`ImageViewerPage`）

* 总开关 + 未启用时的告警条；
* **格式绑定**折叠面板：按**格式分组**列出（PNG / JPEG / BMP / GIF / TIFF / 图标 /
  JPEG XR / WebP / HEIF / AVIF），同一格式的多个别名（如 `.jpg`/`.jpeg`/`.jfif`/`.jpe`）
  合成一行勾选；勾选即绑定该组全部扩展名；
* 本机解码能力**运行时探测**（`ImageCodecInfo.GetImageDecoders()`）：
  没有装 WebP/HEIF/AVIF 系统扩展的机器上，那几行会被标注「（系统不支持解码）」并禁用，
  而不是等用户双击图片才失败。三态复选框用于表示「部分绑定」，点击后会被强制落回确定状态，
  避免用户点出「既非选也非不选」；
* 自定义扩展名输入（回车或按钮添加，带格式校验与重复检测）；
* **系统关联**：写入 / 清除关联按钮、打开系统默认应用设置、以及实时状态行
  （已绑定扩展名 + 其中多少个确实写进了注册表）；
* **查看器窗口**：多实例、任务栏、边缘吸附、记住位置、打开时适应窗口、自动保存批注、留白背景色；
* 「打开一张图片测试」按钮，未启用总开关时禁用。

## 4. 画布：图片作为底图的独立画布

### 4.1 基类打开的扩展点（`IndependentCanvas`）

原来的独立画布是 `sealed`，且尺寸、变换、内容层级全部写死。为了让它能被图片查看器复用，
在**不改变原有行为**的前提下开了三个口子：

| 扩展点 | 作用 |
| --- | --- |
| `BackgroundLayer`（`protected Canvas`） | 墨迹**之下**、同一坐标系的一层空画布。基类保持为空且不接收命中测试，派生宿主在这里放图片底图 |
| `ApplyInkTransform(Matrix)`（`protected`） | 把**任意仿射增量**烘焙进笔迹点集。原来的 `ApplyShift(Vector)` 变成它的平移特例 |
| `AutoSizeToViewport`（`public bool`，默认 `true`） | 为 `false` 时不再把 `Width/Height` 钉到视口尺寸，交给父容器布局（填充式宿主） |
| `ResetInkTransformWithoutMovingStrokes()`（`protected`） | 换内容时把渐隐层的累积变换归零，但不动笔迹 |
| `RequiresInputWhenIdle`（`public virtual bool`，默认 `false`） | 非批注状态下是否仍接收输入。图片查看器覆写为 `true`（要用手势平移缩放），不落墨改由 `EditingMode = None` 保证。见 §13.2 |
| `HostControlsOverlaySuppression`（`public virtual bool`，默认 `true`） | 是否接受宿主按批注状态暂停浮层。图片查看器覆写为 `false`，撤销/恢复按钮不因切到鼠标模式而消失。见 §13.2 |

顺带做的一个修正：渐隐层原来用 `TranslateTransform` 逐次累加，现在改成
`MatrixTransform` + 累积矩阵，因此**缩放/旋转也能同步到渐隐视觉**（原来只支持平移）。

### 4.2 坐标不变式与视图矩阵

`ImageViewerCanvas` 维护一个视图矩阵 `M`：**视口坐标 = M × 图片像素坐标**，
`M = Scale(zoom) · Rotate(角度) · Translate(平移)`。

* 图片：`Image` 元素的 `RenderTransform = MatrixTransform(M)`，走 GPU，缩放旋转不掉帧；
* 墨迹：走基类的 `ApplyInkTransform`，把变换**烘焙进笔迹点集**。

视图矩阵从 `M0` 变到 `M1` 时，笔迹需要的视口空间增量是 `delta = M0⁻¹ · M1`：

```
点 s 在视口里 → 对应的图片点 i = M0⁻¹·s → 新位置应为 M1·i = M1·M0⁻¹·s
```

因为变换被真实写进点集，**橡皮擦命中测试、框选、坐标换算全都不需要知道视图的存在**
（继承基类「笔迹数据坐标 == 视觉坐标」的不变式）。基类渐隐层的累积矩阵与 `M` 始终相等
（起点都是单位矩阵，每次乘同一个 delta），所以激光笔渐隐视觉也不会与墨迹错位。

### 4.3 缩放 / 旋转 / 平移

| 操作 | 行为 |
| --- | --- |
| 滚轮 / `+` `-` / 放大缩小按钮 | **以光标（或视口中心）为锚点平滑缩放**：锚点下方的图片内容保持不动。缩放范围 2% ~ 3200%，见 §14.2 |
| 顺时针 / 逆时针旋转按钮、`R` / `Shift+R` | 绕**当前可见图片包围盒的中心**旋转 ±90°（「看到什么就绕什么转」，内容不会跳出视野） |
| 中键 / 右键 / `空格`或`Ctrl` + 左键拖动 | 平移图片（任何状态都可用） |
| 左键拖动（**非批注状态**） | 平移图片（与触摸单指一致，见 §14.1） |
| 单指拖动 / 双指捏合（触摸） | 见 §14.1 |
| `Ctrl+0` / `Ctrl+1` | 适应窗口 / 原始大小 |
| 窗口尺寸变化 | 「适应窗口」模式下自动重新适配，否则夹紧视图 |

**平移夹紧**（`ClampAndApply`）：图片比视口小时整体居中，比视口大时不允许拖出空边。
既是主流看图软件的手感，也保证批注区域始终对着图片内容。
捏合 / 以光标为中心缩放 / 旋转同样要经过它 —— 否则手势会把手里的图片直接推出视野。

### 4.4 图片解码

* 用 `BitmapFrame.Create(stream, PreservePixelFormat, BitmapCacheOption.OnLoad)`：
  一次读完即释放文件句柄，用户随后可以移动/删除那张图；
* **按 EXIF 方向标签（`/app1/ifd/{ushort=274}`）转正**，手机照片不会躺着显示；
* 解码失败弹窗 + 日志；若一张图都没打开成功，窗口自动关闭，不留空壳。

## 5. 窗口：自定义边框、吸附、不越界

### 5.1 命中测试（`WM_NCHITTEST`）

窗口是 `WindowStyle=None` + `ResizeMode=CanResize`，边框、移动、吸附全部**交给 Windows 自己完成**：

| 区域 | 返回 | 效果 |
| --- | --- | --- |
| 窗口外框 7 DIP | `HTLEFT/HTRIGHT/HTTOP/HTBOTTOM/HTxxx` 系列 | 系统缩放 |
| 底栏按钮之外的空白处 | `HTCAPTION` | 系统拖动 |
| 图片之外的留白（letterbox） | `HTCAPTION` | 系统拖动 |
| `Alt` + 任意位置 | `HTCAPTION` | 图片铺满视口时的拖窗逃生口 |
| 其余（图片上、全屏时） | `HTCLIENT` | 批注书写 |

把拖动交回系统，等于**免费获得**：

* Aero Snap —— 拖到顶部放开 → 最大化；拖到左/右侧放开 → 左/右半屏分屏（正是需求里的分屏）；
* 拖动过程中窗口不会被拖出屏幕范围；
* 双击底栏空白处 → 最大化 / 还原（系统标题栏惯例）。

底栏按钮用**几何边界**判定（`IsOverBarButton` 遍历三组按钮的 `ActualWidth/Height` +
`TranslatePoint`），比视觉树命中测试更确定，也不会把 1px 的分隔线误判成拖动区。

### 5.2 最大化边界（`WM_GETMINMAXINFO`）

* 最大化时贴合**显示器工作区**（不盖任务栏）；全屏时贴合**整块显示器**；
* `ptMaxTrackSize` 限制为显示器尺寸 → **窗口本体永远不超出屏幕**；
* `ptMinTrackSize` 取自 `MinWidth/MinHeight` 并按 DPI 换算。

### 5.3 全屏

全屏 = `_fullScreenActive` + `WindowState=Maximized`（此时 `WM_GETMINMAXINFO` 用显示器全bounds）
+ `Topmost` + 隐藏底栏 + 按钮图标切成「退出全屏」。`Esc` 退出；退出时先回 `Normal` 再按需重设
`Maximized`（用 `Dispatcher.BeginInvoke` 让系统重新计算边界）。

### 5.4 位置记忆与不越界

* 打开时若开启「记住窗口位置」且记录过位置就沿用，否则在**鼠标所在显示器**的工作区居中并缩放；
* 无论哪条路径，最后都过一遍 `ClampIntoVirtualScreen()`：宽高不超过虚拟屏幕，
  并保证至少 120×80 留在可见区域内 —— 避免「上次在副屏、这次副屏没接」导致窗口消失在屏幕外；
* 关闭时（`WindowState != Normal` 用 `RestoreBounds`）写回设置。

## 6. 底部扩展栏

```
┌─ 左组 ────────────────┐ ┌─ 中组 ─────────────────────────────────────┐ ┌─ 右组 ─────────────────┐
│ ‹    📁    ›          │ │ 🔍+  🔍− │ ⟳  ⟲ │ ⚙     │ ✎              │ │ − │ ▢ ⛶ │ ✕            │
│ 上一张 文件夹 下一张   │ │ 放大 缩小│顺时针 逆时针│图像调整│ 墨迹书写  │ │最小化│最大化 全屏│关闭   │
└───────────────────────┘ └────────────────────────────────────────────┘ └────────────────────────┘
```

* **图标在上、文字说明在下**：每个按钮是「Segoe Fluent Icons 图标 + 10.5px 文字」的竖排
  `StackPanel`，按钮最小尺寸 **60×54 DIP**、底栏高 62 —— 触摸屏上手指点得到
  （原来只有图标、38×32，触摸基本按不准）；
* 图标用 Segoe Fluent Icons / Segoe MDL2 Assets 回退字体；「逆时针」用同一个旋转箭头
  **水平镜像**得到（图标集只有一个旋转箭头），语义不会歧义；
* **「墨迹书写」按钮**位于中组最右侧（用分隔线与视图按钮分开），点击即让**主工具栏**
  进入/退出批注模式，见 §13。按钮用强调色高亮表示当前是否正在批注；
* 每个按钮都设了 `AutomationProperties.Name/HelpText`（内容是图标+文字面板，UIA 默认取不到
  可读名称，读屏软件与自动化脚本会只看到无名按钮）；
* 底栏空白处是拖动区（见 5.1）；右下角有缩放手柄的视觉提示（真正的命中仍在边框）；
* 视口右下角保留独立画布自带的**撤销/恢复**圆形按钮（批注需要，且不属于底栏按钮组）。

「图像调整」弹出一个面板：亮度 / 对比度 / 饱和度滑杆 + 重置。
三个滑杆都过 `SliderTouchHelper.AddTouchSupport`（WPF 滑杆默认按鼠标处理，手指拖动会退化成
一次点击）。滑杆拖动用 140ms 防抖合并，松手后必然再算一遍；关闭再打开面板**不会重置**
已应用的调整（滑杆与画面上看到的效果始终一致），只有「换图」和「重置」按钮才清零。

> `.NET Core` 版 WPF 没有移植 `ThumbnailToolBar` / `ThumbnailToolBarButton`
> （它们依赖 ITaskbarList3 的 COM 封装），所以任务栏只用 `TaskbarItemInfo` 在 .NET 上
> 确实可用的部分。

## 7. 任务栏与多实例

* 每个查看器窗口都是**独立顶层窗口**且 `ShowInTaskbar=true`，加上进程的 AppUserModelID
  （`InkCanvasForClass.CE`）与主程序一致，Windows 会把它们归到同一个任务栏按钮下，
  **为每个窗口显示实时缩略图预览**，点哪个就单独唤起到前台 —— 这就是需求里
  「最小化后按图片分别唤起」的实现方式，不需要自己写 ITaskbarList3；
* `TaskbarItemInfo.ThumbnailClipMargin` 按画布在窗口中的位置计算，把底栏裁出预览之外，
  缩略图里只有图片本身；`Description` 显示「文件名 · 宽×高」；
* 窗口从最小化恢复用 `ActivateFromTaskbar()`（`Minimized → Normal` + `Show/Activate/Focus`）；
* `ImageViewerManager` 用一把锁维护实例列表：同一张图片已经打开时**只把它的窗口唤到前台**，
  不会产生重复窗口；`MultiInstance=false` 时后打开的图片复用最近一个窗口换图
  （换图前会先保存旧图的批注）。

## 8. 批注持久化

`ImageViewerAnnotationStore` 把批注按图片存到 `<程序目录>/Configs/ImageViewerInk/`，
文件名为 `sha1(全路径小写)[0..16]_原文件名.isf`（ISF = WPF `StrokeCollection` 原生序列化）。
不写在图片旁边，不污染用户文件夹；带原文件名是为了人工可辨认。

**坐标约定是这块的关键**：落盘的笔迹点一律在**图片像素坐标系**里。

* 保存：`strokes.Clone()` 后用 **`M⁻¹`** 把视口坐标换算回图片坐标，再写文件；
* 载入：读出的笔迹用**当前 `M`** 正变换回视口坐标，然后加入画布并 `ResetInkHistory()`
  （历史从零开始，载入历史批注不算一步可撤销操作）。

于是批注永远锚在图片的**同一处内容**上，与保存当时的缩放/旋转/窗口大小无关。
窗口关闭、切换上一张/下一张、切换单实例窗口里的图片时都会先保存当前图。

## 9. 图像调整

`ImageAdjustment.Apply(source, brightness, contrast, saturation)`：

* 亮度 + 对比度先合成 256 项查找表：`v' = clamp((v + b·255 − 128)·(1+c) + 128)`；
* 饱和度按 Rec.601 亮度混合：`v' = lum + (v − lum)·(1+s)`（`s = −100` 即灰度）；
* alpha 原样保留，PNG 透明区域不会变黑；
* **横向分块**读写（每块约 1MB），内存与图片大小无关；
* 超过 16MP 的图先等比缩小再处理（调整是观感层面的操作，不值得为 48MP 一次吃掉几百 MB）。

## 12. 已知取舍与后续可做项

1. **无法程序化设为默认应用**：Windows 的 `UserChoice` 有哈希保护，只能引导用户去系统设置确认
   （设置页已提供按钮）。这是平台限制，任何程序都绕不过去。
2. **留白处拖动 = 移动窗口**：因此**图片之外的区域不能起笔写批注**（图片上的左键在批注状态下仍是书写）。
   这是「空白区域可拖动独立画布位置」与「画布可批注」两条需求之间的直接取舍；
   非批注状态下图片上的拖动改为平移图片，`Alt`+拖动与底栏空白拖动是图片铺满视口时的替代拖窗方式。
3. **平移夹紧默认开启**（`ConstrainPanning`，代码里可关）：图片比视口小时居中、比视口大时不留缝，
   因此**适应窗口状态下拖不动图片**（整张都看得见，本来也没地方可拖）——这是主流看图软件的行为。
4. **任务栏缩略图工具栏按钮**在 .NET Core WPF 上不可用（见 §6 注释）；
   若确实需要，得自己封装 `ITaskbarList3::ThumbBarAddButtons`。
5. **批注不随图片一起导出**：目前只单独存 ISF；「把批注合成进图片另存为」还没做。
6. 查看器内的笔属性（颜色/粗细）直接复用主画布当前画笔；
   尚未提供查看器专属的画笔调节入口。
7. 超大图（>16MP）应用图像调整时会先降采样，100% 放大查看时锐度会略降。
8. **主画布的几何橡皮擦不转发到查看器窗口**：工具栏切到橡皮时查看器画布进入
   `EraseByPoint`/`EraseByStroke`，走的是 InkCanvas 原生擦除、擦头形状与主画布一致；
   但 `MW_Eraser` 那套「按点位解析实例的自绘擦除」只覆盖主画布与 UI 联动画布
   （查看器是独立顶层窗口，主画布的命中测试够不到）。
9. **触摸手势按两指处理**：三指及以上会参与质心/离散度计算（等价于「更多手指 = 更强的缩放」），
   没有实现旋转手势与惯性滑动。

## 13. 批注状态跟随主工具栏

这是本次追加的核心要求：**主工具栏进入批注状态时，可以直接在内置图片查看器上书写，
行为与 UI 联动用的独立画布完全一致。**

### 13.1 做法：把状态同步抽成一份共用实现

原来这套逻辑写在 `MW_UILinkage.SyncUILinkageCanvasState()` 里，只作用于 UI 联动画布。
现在的结构是：

```
MainWindow.SyncUILinkageCanvasState()          ← 250ms 轮询的一个阶段 + 工具切换时的立即调用
  ├─ GetUILinkageEffectiveEditingMode()        ← 逻辑工具（_currentToolMode）→ 目标编辑模式
  ├─ BuildIndependentCanvasSyncContext()       ← 采集主画布侧快照（笔属性 / 橡皮形状 / 手掌擦工厂）
  ├─ foreach UI 联动画布  : IndependentCanvasStateSync.Apply(canvas, ctx)
  ├─ foreach 查看器画布   : IndependentCanvasStateSync.Apply(canvas, ctx)   ← 同一份实现
  └─ IndependentCanvasStateSync.NotifyAnnotationState(interactive)          ← 刷新底栏按钮高亮
```

`IndependentCanvasStateSync.Apply` 推送四类状态：

| 状态 | 来源 | 说明 |
| --- | --- | --- |
| `EditingMode` | 逻辑工具 | pen/color → `Ink`；eraser → `EraseByPoint`；eraserByStrokes → `EraseByStroke`；select → `Select`；cursor/shape/roaming → `None` |
| `DrawingAttributes` | 主画布 `DefaultDrawingAttributes` | **整体克隆**，颜色/粗细/荧光笔/笔尖/压感/曲线拟合全部跟随（只比 Color/Width/Height 会让画布停在默认硬笔上） |
| `EraserShape` | 主画布 `EraserShape` | 原生擦除的擦头形状与主画布一致 |
| 手掌擦 / 触摸抑制 | `BuildPalmEraserPolicy` | 与主画布共用同一套接触面积判定与设置 |

**关键点：`_currentToolMode` 是逻辑工具，不是物理 `EditingMode`。**
原生湿墨迹管线激活时物理模式是 `None`，若按物理模式判定会把卫星画布错误禁用、书写落到主画布 ——
所以两端都必须用逻辑工具换算。

### 13.2 少数能力差异由画布自己声明

两类画布不能一模一样地对待，否则图片查看器会被「禁用输入」：

| 虚成员 | UI 联动批注层 | 图片查看器画布 | 原因 |
| --- | --- | --- | --- |
| `RequiresInputWhenIdle` | `false` | `true` | 查看器在鼠标/漫游模式下仍要用鼠标拖动与双指手势平移缩放图片；不落墨改由 `EditingMode = None` 保证 |
| `HostControlsOverlaySuppression` | `true` | `false` | 查看器滚动条本就隐藏，而撤销/恢复圆按钮是批注主要入口，不该因切到鼠标模式而消失 |

另外两处共用实现里的必要处理：

* `TouchSuppressionEnabled` 两边都恒为 `true`：卫星画布上两根手指永远不该产生笔迹。
  非批注状态下 `EditingMode` 已是 `None`，抑制逻辑自然不会改动任何状态。
  （UI 联动在非批注时 `IsHitTestVisible=false`，触摸事件根本到不了画布，因此没有额外开销。）
* `TouchUserEditingMode` 用 `EffectiveMode` 而不是「`Ink` / `None` 二选一」：
  框选工具下被抑制的那一笔应当恢复到 `Select` 而不是 `Ink`，否则手势结束会莫名其妙变成笔。
* **手掌擦只在批注状态下挂接**：查看器非批注也接收输入，此时若挂着手掌擦，
  鼠标模式下把手掌搁在图片上会把画布切成 `EraseByPoint` 并擦掉批注。
  判定委托由工厂按画布创建一次，内部实时读取 `canvas.IsPalmErasing`（原实现把该值在创建时冻结了，
  「已在擦除中」这条分支实际从未生效）。

### 13.3 及时性：不等下一拍

常规路径是 250ms 轮询，但工具切换与点击「墨迹书写」之后必须立刻生效，
否则会出现「点了批注还要等一下才能写」的迟滞。因此：

* `UpdateCurrentToolMode()` 末尾新增 `SyncSatelliteCanvasStateNow()`，
  让状态在工具变更的同一拍推下去；
* 查看器底栏的「墨迹书写」按钮点击后额外主动同步一次。

### 13.4 全局 Ctrl+Z / Ctrl+Y 分派到查看器

ICC 的撤销/重做是**系统级热键**（`GlobalHotkeyManager` 用 `RegisterHotKey` 注册 Ctrl+Z / Ctrl+Y），
查看器窗口根本收不到这两个键。若不处理，用户在图片上写错后按 Ctrl+Z，
撤销掉的会是**白板内容**，而图片上的错误笔迹还在 —— 这正是当年给 UI 联动画布修过的同一个坑。

做法（`MW_InkActivity`）：查看器画布与 UI 联动画布一样，只把「**落笔**」当成活动信号
（绝不挂 `StrokesChanged`：缩放/平移会逐帧改笔迹几何，把它当活动信号会导致
「只是拖了一下图片，Ctrl+Z 就被劫持」）。两边各自记录时间戳，
`GetActiveUILinkageCanvas()` 按新鲜度取更近的那一块画布：

```
viewerFresh && (!uiLinkageFresh || viewerUtc > _lastInkActivityUtc)  → 查看器画布
否则走原来的 UI 联动判定
```

窗口关闭时清掉指向它的活动记录，避免撤销落到一块已死的画布上。

## 14. 触摸屏适配与平滑缩放

### 14.1 触摸交互

| 手势 | 批注状态 | 非批注状态 |
| --- | --- | --- |
| 单指拖动 | 书写批注 | 平移图片 |
| 双指捏合 + 拖动 | 以两指质心为锚点缩放 + 平移 | 同左 |

* 手势由画布自己实现（不打开 WPF 的 `IsManipulationEnabled`）：
  单指/多指位置在 `PreviewTouchDown/Move/Up` 里维护，**不设 `Handled`** ——
  基类挂在 InkCanvas 上的多指抑制与手掌擦必须照常收事件，
  「手指永远不会在图上留下误笔迹」的既有语义因此在查看器里同样成立。
* 双指每帧把「质心位移（平移）」与「平均离散度之比（缩放）」**合并成一次视图重建**：
  用上一次的质心算出对应的图片锚点，再让新质心落在同一个图片点上。
  分两步（先平移再缩放）会让缩放锚点用到已经过期的质心，手指快速捏合时内容会「追不上」。
* **性能**：基类原来在每次单指落下时都克隆一次全量笔迹（用于多指误笔回滚）。
  现在只有可能落墨的模式（`Ink` / `Select`）才克隆 —— 触摸屏上每次落指克隆几百条笔迹
  是实打实的卡顿来源，而查看器「始终接收输入」，受影响最明显。
* 触摸友好的尺寸：底栏按钮 60×54、底栏高 62；边框命中宽度从 7 DIP 提到 **10 DIP**
  （手指按不准，边框太窄会变成「一拖就移动窗口」）；调整面板滑杆显式接入 `SliderTouchHelper`。
* 指针反馈：批注状态十字、鼠标模式四向箭头（可拖动），内层 `InkCanvas` 的指针被清空，
  保证指针始终由窗口按「当前能不能写」决定。

### 14.2 平滑缩放

缩放分两条路径：

* **滚轮 / 按钮 / 快捷键** → `AnimateZoom(factor, anchor)`：
  只更新**目标倍率**，实际变换由 `CompositionTarget.Rendering` 逐帧逼近，
  每帧按 `1 − e^(−dt/τ)`（τ = 60ms）施加增量。
  - 帧率无关：掉帧时每帧步进更大，观感一致；
  - 连续多次调用（滚轮连滚、长按按钮）**累积到同一个目标值**上共用一段缓动，
    而不是每格重新起一段 —— 这是滚轮缩放「顺滑」的关键；
  - 收敛到相对误差 0.15% 内即吸附到目标值并结束动画。
* **双指捏合** → 直接按帧比值施加（本身就是连续的，不需要再叠一层缓动）。

动画期间把图片重采样降到 `LowQuality`，结束/被手势接管时恢复 `HighQuality`；
换图、适应窗口、原始大小、旋转都会先 `CancelZoomAnimation()`。
动画挂在**静态**的 `CompositionTarget.Rendering` 上，因此窗口关闭时必须停掉
（已接在 `OnWindowClosing`），否则回调会继续跑在一棵断开的视觉树上。

## 15. 本次追加改动中的代码审查修正

无法实机驱动输入的部分靠通读代码兜底，过程中修掉了 4 个真实缺陷，
都是「能编译、能显示，但一用就出问题」的类型：

| # | 缺陷 | 后果 | 修正 |
| --- | --- | --- | --- |
| 1 | 非批注状态下「图上左键拖动 = 平移图片」未排除画布内部控件 | 隧道路由下画布处理器先于按钮执行，**撤销/恢复圆按钮、提示条关闭按钮彻底点不动** | 新增 `IsInteractiveChild()`，事件源位于按钮/滑杆/滚动条上时不启动平移 |
| 2 | 只监听窗口 `SizeChanged`，漏掉画布自身尺寸变化 | 「适应窗口」用了**过期视口**，图片被裁掉一截（实测 92% 的图被算成 97% 并溢出） | 同时挂 `ViewerCanvas.SizeChanged` |
| 3 | `RebuildViewKeepingPointFixed` 直接施加平移、不走夹紧 | 捏合、以光标为中心缩放、旋转可以**把图片推出视野且不回收** | 改为收敛到 `ClampAndApply()` |
| 4 | 平滑缩放动画挂在静态 `CompositionTarget.Rendering` 上，关闭窗口未退订 | 回调继续跑在已断开的视觉树上 | `OnWindowClosing` 调用 `CancelZoomAnimation()` |

另外两处顺带改善：`IndependentCanvasStateSync` 里手掌擦委托改为按画布创建一次、
内部实时读取 `IsPalmErasing`（修掉「已在擦除中」分支从未生效的问题）；
底栏按钮补上 `AutomationProperties.Name/HelpText`（内容是图标+文字面板，UIA 取不到可读名称）。

## 16. 第三轮：专属图标 / 标题栏 / 最大化 / 全屏 / 设置项修正

### 16.1 专属图标（复用「创建快捷方式」的图标生成器）

沿用 `UriSchemeShortcutHelper` 那套徽章生成器（圆角白底 + 程序内图标 + 右下角 ICC 角标），
新增 `FeatureImageViewer` 与 `EnsureImageViewerIconFile()`，**程序内图标换成图片查看器图标**
（`SegoeFluentIcons.Photo`）—— 也就是「通用 → 创建快捷方式」那块按钮用的同一个生成器。

顺带把它从「只输出一张 256px」升级为**多尺寸 ICO**（16/32/48/256，每帧 PNG 压缩条目）：
任务栏与标题栏按 16~48 显示，只给 256 会被系统缩成糊图；小于 48 的帧不再画 ICC 角标
（那几像素画出来只是污点）。多尺寸同样惠及既有的快捷方式图标。

图标路径被三处共用：窗口 `Icon` + 标题栏左端图标、注册表 `DefaultIcon`
（ProgId 与 `Applications\<exe>` 各一份）、以及任务栏「固定到任务栏」的
`RelaunchIconResource`。生成失败时全部回退到主程序 exe 图标，不会出现无图标窗口。

### 16.2 「打开方式」里的名字与任务栏分组

* `Applications\InkCanvasForClass.exe\FriendlyAppName` = **"Ink Canvas 图片查看器"** ——
  资源管理器「打开方式」列表显示的就是这个名字（这是 Explorer 的取值来源）；
* 任务栏分组改用**窗口级** AppUserModelID：`InkCanvasForClass.CE.ImageViewer`。
  进程级的 `SetCurrentProcessExplicitAppUserModelID` 让同进程所有顶层窗口挤在一个任务栏按钮下，
  查看器必须单独一组才不会和设置窗口/主界面混在一起。
  实现见 `WindowAppIdentity`：`SHGetPropertyStoreForWindow` +
  `PKEY_AppUserModel_ID` / `RelaunchDisplayNameResource` / `RelaunchIconResource`，
  COM 互操作直接复用 `EdgeGestureUtil` 里已有的 `IPropertyStore`/`PropertyKey`/`PropVariant` 声明
  （只把 `pwszVal` 由 private 改为 public）。
  写入后**立刻读回校验**，不一致就写一条 Warning —— 这类「静默不生效」最难查。

### 16.4 最大化不完全（修复）

`WindowStyle=None` + `ResizeMode=CanResize` 的窗口仍带 `WS_THICKFRAME`，
Windows 最大化时会把**不可见的边框**算进去：不补偿就会「窗口比工作区大一圈、被顶到左上方」，
右下两条边反而超出屏幕。

修法是在 `WM_GETMINMAXINFO` 里按边框厚度补偿：

```
ptMaxPosition = 工作区(或整块显示器) 左上 − 显示器原点 − frame
ptMaxSize     = 工作区尺寸 + frame × 2      // 让「可见区域」正好等于工作区
```

`frame` 取**实测值**（当前窗口矩形 − 客户区矩形）÷ 2，而不是
`SM_CXSIZEFRAME + SM_CXPADDEDBORDER`：后者在这台机器上算出来是 8，实测是 7，
差 1px 就会让最大化后越界/留缝。实测不可用时才退回系统度量。

### 16.5 全屏无法退出（修复）

原因很直接：进入全屏时把底栏隐藏了，而「退出全屏」按钮就在底栏上 ——
**唯一的出口只剩 Esc**，窗口一旦没拿到键盘焦点就等于「进得去出不来」。

修法：全屏时显式留出口 —— 画布右上角浮现一个半透明「退出全屏」胶囊按钮
（`BtnExitFullScreen`，带 `AutomationProperties.Name`，UIA/读屏都能拿到），
同时进入全屏后主动 `Activate()` + `Focus()` 保证 Esc 一定生效。

## 17. 修复「标题栏上方多余的白色边框」

### 17.1 定位过程（先量再改）

不猜、直接量像素。把窗口左上角逐像素扫出来后发现：

| 位置 | 实测 |
| --- | --- |
| 标题栏起始行 | 客户区顶部往下第 **7** 行（`y=0..6` 是那条多余的边） |
| 那条边的颜色 | `#F3F3F3`（近白），横跨整个标题栏宽度 |
| 窗口矩形 vs 客户区 | `1180x800` vs `1166x786` → **四周各 7px 非客户区** |
| 窗口样式 | `0x160F0000`：**有 `WS_THICKFRAME`，无 `WS_CAPTION`** |

再做了一次排除实验：把窗口整体移动三次（换掉窗口后面的内容），那条边的颜色**始终是 `#F3F3F3`**——
所以它不是「桌面透过窗框漏进来」，而是**这一圈边框自己按系统主题涂色**：
本窗口 `WindowStyle=None` 没有标题栏，没有任何内容去绘制这圈非客户区，
浅色主题下系统就把它涂成了近白色。这就是「标题栏上方多出来的白色边框」。

### 17.2 修法

1. **`WM_NCCALCSIZE` 返回 0**（`HandleNonClientCalcSize`）：声明「客户区 == 整个窗口」，
   那圈非客户区直接不复存在，也就没有「该涂什么颜色」的问题。
   附带好处：最大化/全屏的可见区域**正好**等于目标矩形（边框补偿实测变成 0）。
   缩放、边缘吸附、最大化边界都不受影响 —— 它们走 `WM_NCHITTEST` / `WM_GETMINMAXINFO`。
2. **`ForceClientAreaRelayout()`**：`WM_NCCALCSIZE` 只改「客户区算多大」，本身不产生 `WM_SIZE`。
   不补这一下，WPF 的根视觉会停在旧尺寸上，**四周会留出一圈未绘制的白边**
   （实测：只加上第 1 步会出现左侧/底部白条，最大化过一次才正常 —— 那正是"来了一个真实的 WM_SIZE"）。
   这里把尺寸推 1px 再复原，走的是与用户手动缩放完全相同的代码路径，肉眼看不到中间态。
3. **`DWMWA_USE_IMMERSIVE_DARK_MODE`**：让 DWM 按深色绘制窗口边框/圆角装饰，
   免得它在别处又按浅色主题描一条浅边。属性编号 1809~1909 是 19、2004+/Win11 是 20，两个都试。

> 中途试过、但**没有采用**的方案：保留那圈非客户区、自己用 `WM_NCPAINT` 把它涂成深色。
> 白色确实消失了（实测变成 `#1A2031`，DWM 自己又叠了一层），但它**会破坏最大化**——
> 实测点了「最大化」窗口仍是 `1180x800` 不动。既然根因是"这圈边框不该存在"，就按根因修。

### 17.3 复验（隔离副本实机）

| 状态 | 窗口矩形 | 客户区 | 目标矩形 | 顶部像素（y=0..8） |
| --- | --- | --- | --- | --- |
| 普通 | 1180x800 | **1180x800**（= 窗口，边框已取消） | — | `4B4B4B`（本应有的 1px 描边）+ `151515`… |
| 最大化 | 2560x1392 | 2560x1392 | 工作区 2560x1392 ✅ 完全一致 | 同上，**无白色带** |
| 全屏 | 2560x1440 | 2560x1440 | 显示器 2560x1440 ✅ | 同上 |
| 退出全屏 | 2560x1392 | 2560x1392 | ✅ 回到进入前的最大化 | 同上 |

同时截图确认：标题栏（图标 + `c.png - Ink Canvas 图片查看器` + 最小化/最大化/关闭）在最顶端，
